码上传：把文字装进二维码，让文档走光路。

面向经授权的隔离环境文档转录。文字自动压缩，二维码按实际容量分页，另一台设备扫码收齐后校验并还原。没有文档上传服务，也没有账户、云盘或复杂参数。

01 / 五步完成转录

  1. 输入文字

    发送端选择“生成二维码”，粘贴文档、Markdown 或代码，或导入一个 UTF-8 文本文件。容量会自动计算，不需要手动构建。不支持 Word / PDF 提取或文件夹。

  2. 展示二维码

    先静态试扫，之后可翻页、输入页码、全屏或每秒一页循环播放。二维码很密时先全屏；仍难扫描时开启“更易扫描”，并清空接收端重新开始。

  3. 在另一台设备接收

    打开同一工具的“扫码接收”，选择摄像头，允许访问并开始扫描；也可导入多张二维码原图。支持乱序和重复扫码，普通扫码应用不能直接恢复此协议。

  4. 补齐缺页

    复制接收端的“缺失页码”，在发送端“补页”输入相同范围，例如 2, 5-8。只播放这些页；“全部页”恢复完整列表。

  5. 校验并导出

    收齐后自动检查长度与 CRC32。只有“校验通过”才可复制全文或下载 document.txt。下载保留未编辑导入文件的 UTF-8 字节、BOM、CRLF 与尾部空格。

02 / 扫描与容量

默认最高 Version 40、ECC L，每页使用容纳数据的最小版本。2,953 字节总容量减去 36 字节头部，正文最多 2,917 字节。中文字符数与字节数不同，压缩率也因文档而异。

  • “更易扫描”使用最高 Version 30、ECC M，以更多页换取较低密度。
  • 保持白色边缘完整入镜，避免反光。小于 3 px / 模块时应扩大显示。
  • 摄像头需要 HTTPS / localhost 和浏览器许可；公司策略也必须允许。
  • 图片最多 32 MiB / 1600 万像素。摄像头跟不上时暂停播放、手动翻页。

03 / 严格环境的边界

仅用于你拥有或明确获准导出的文档。文档分级、接收设备、屏幕拍摄和保存位置均应先获得组织批准。

压缩不是加密。CRC32 不是身份认证。

获得二维码的人可以还原文档。本工具不绕过 DLP 或审批、不提供企业安全认证、访问控制或审计。如果组织禁止此类传输，请不要使用。

04 / 真正离线，不依赖外网

在获准的联网设备下载离线包，按合规流程带入目标环境。解压后，在 qrmax-transfer/ 的父目录启动已有的本地静态服务器：

python3 -m http.server 8080 --bind 127.0.0.1

浏览器打开 http://127.0.0.1:8080/qrmax-transfer/。两端各自运行本机服务即可，不需要 npm 或互联网。需要预先可用的服务器，不要双击 HTML；模块 Worker 需要 HTTP(S)。绑定地址仅对本机开放。

在线访问与本机离线是两件事。

在线版会向 GitHub Pages 请求静态资源，托管方可能记录访问元数据，但文档不会上传。没有 Service Worker，不保证断网后重开远程网址。已收到的页面和原文只在内存中，刷新即丢失。

05 / 开始前的验收清单

  • 确认组织批准本次文档、设备与传输方式。
  • 用目标屏幕与真实摄像头试传一段非敏感文字，再试一个多页文档。
  • 演练补页，确认收齐后输出内容完整；图片解码测试不能替代真实摄像头验收。
  • 按公司要求管理下载、剪贴板、截图和录像等页面外副本。传输时不要刷新页面。

MaUpload: pack text into QR. Move documents through light.

A local-first workstation for authorized document transcription in isolated environments. Text is compressed and split into QR pages. A second device scans, verifies and restores the complete document. No document upload service, accounts or cloud drives.

01 / Five steps to transcription

  1. Enter text

    Choose Generate QR on the sender. Paste a document, Markdown or code, or import one UTF-8 text file. Capacity is calculated automatically. Word / PDF extraction and folders are not supported.

  2. Display QR pages

    Try a static scan first. Step through pages, enter a page number, use fullscreen or enable one-second autoplay. For dense QR codes, use fullscreen first. If needed, enable Easier scanning, clear the receiver and start again.

  3. Receive on another device

    Open Receive QR in the same tool, select a camera, allow access and start scanning. You can also import multiple original QR images. Unordered pages and duplicates are supported. Standard QR readers cannot directly restore QMT2 documents.

  4. Resend missing pages

    Copy Missing pages from the receiver and enter the same range in Resend on the sender, such as 2, 5-8. Play just those pages. All pages restores the full playlist.

  5. Verify and export

    The complete document is checked for length and CRC32. Only Verified documents can be copied or downloaded as document.txt. Downloads preserve an unedited imported file's UTF-8 bytes, BOM, CRLF and trailing spaces.

02 / Scanning and capacity

Default: up to Version 40, ECC L, using the smallest version that fits each page. A maximum 2,953-byte QR minus its 36-byte header leaves 2,917 payload bytes. Character count is not byte count, and compression varies by document.

  • Easier scanning uses up to Version 30, ECC M, trading more pages for lower density.
  • Keep the full white border visible and avoid glare. Enlarge the display below 3 pixels per module.
  • Cameras need HTTPS / localhost, browser permission and organization approval.
  • Images are limited to 32 MiB / 16 megapixels. Pause and step manually if the camera cannot keep up.

03 / Restricted environments

Transfer only documents you own or are explicitly authorized to export. Your organization must approve classification, destination devices, screen capture and storage locations.

Compression is not encryption. CRC32 is not authentication.

Anyone with the QR pages can restore the document. This tool does not bypass DLP or approvals and provides no enterprise security certification, access controls or audit trail. Do not use it where such transfers are prohibited.

04 / Fully offline operation

Download the offline bundle on an approved connected device and bring it into the target environment through an authorized process. Extract it, then run an existing local static server from the parent of qrmax-transfer/:

python3 -m http.server 8080 --bind 127.0.0.1

Open http://127.0.0.1:8080/qrmax-transfer/. Each device can use its own local server. Neither npm nor internet is needed at runtime. A server must already be available. Do not double-click HTML: module workers need HTTP(S). The binding exposes the server only to the local device.

Online visits and local offline use are different.

The online version requests static files from GitHub Pages, which may record access metadata. Documents are not uploaded. There is no Service Worker; reopening the remote URL offline is not guaranteed. Source text and received pages are memory-only. Reloading loses the session.

05 / Before relying on it

  • Confirm approval for this document, device and transfer method.
  • Use the actual screen and physical camera to test non-sensitive text, then a multi-page document.
  • Exercise retransmission and verify the full output. Image decoding tests do not replace camera acceptance.
  • Handle downloads, clipboard contents, screenshots and recordings under company policy. Do not reload during transfer.
